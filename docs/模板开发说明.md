## 一、整体目标与背景

### 1.1 项目背景

本项目始于「做一个 OI 大佬风格的个人博客」的需求，中间经历了两次视觉方向修正：

| 阶段 | 诉求 | 结果 |
|---|---|---|
| 阶段一 | OI 大佬风 + Live2D 看板娘 + 大量动效 | Astro 7 完整实现，38 页，但视觉被判定"太丑" |
| 阶段二 | 改为 cnblogs/SilverGo（SimpleMemory）风格 | 等宽极简重做，全站令牌化 |
| 阶段三（当前） | 以 `astro-snow` + `astro-koharu` 为参考，**由 AI 主导提问、逐轮共建**用户自己的理想模板 | R1~R3 完成 |

### 1.2 当前阶段的性质转变

前三阶段是「AI 直接交付成品」，用户不满意即推翻重来。**当前阶段是协作式建构**：

1. AI 先做深入调研（读源码、扒 demo 站、抓 computed style）
2. AI 分轮提问，每个问题给出带取舍说明的选项
3. 用户决策后，AI 逐轮实施，每轮可独立验证
4. 最终产物是一个**开源模板 + 高度可配置**，不是只能自己用的定制站

### 1.3 参考模板调研结论

两个参考仓库已克隆到 `_refs/`，并实测了它们的 demo 站。

#### astro-koharu（原型）

- 仓库：`https://github.com/cosZone/astro-koharu`（v7.7.4）
- Demo：`https://koharu.cosine.ren/`（余弦の博客）
- 技术栈：**Astro 7.1.3 + Tailwind CSS v4 + React 19.2 + @astrojs/node 11**
- 规模：`config/site.yaml` 单文件 879 行配置；`src/` 下约 300 个文件
- 核心能力：
  - 写作室 CMS（CodeMirror 6 + react-hook-form + zod，含加密发布、导入源、链接元数据）
  - 动态 Moments（Node adapter standalone + 远程 suite 拉取，可开关）
  - Shoka 全套 Markdown 语法（容器 / 折叠 / 标签卡 / 注音 / 剧透 / 上下标 / Hexo 标签 / 属性语法）
  - KaTeX、交互答题块、加密文章块、文章落款（colophon）系统
  - i18n 四语（zh/en/ja/ko，Astro i18n routing）
  - 追番 Bangumi、BGM 播放器、圣诞特效、樱花粒子、三级动效档位
  - 4 种评论源（Remark42 / Giscus / Waline / Twikoo）
  - Umami 统计、LQIP 占位图、AI 摘要、语义相似推荐
  - 21 张内置封面、封面波浪分割、`postCardImagePosition: alternating`（图文交替）
- **关键发现**：其技术栈与现有 oiblog（Astro 7.4.2 + Tailwind v4.3.3 + React）**几乎完全一致**，移植成本极低

#### astro-snow（衍生）

- 仓库：`https://github.com/XueHua-s/astro-snow`（v1.0.0）
- Demo：`https://xhblog.top/`（雪花的博客）
- 技术栈：**Astro 5.16 + Tailwind CSS v3 + React 19**（比原型落后一个技术代次）
- 相对 koharu 的改动：
  - ✅ 增加引导页（首屏插画 + 中央白卡）、GitHub Actions 自动部署

  - ✅ 文章页按 `date` 自动生成路径（`/post/number`）

  - ✅ 优化 header 背景动画

### 1.4 最终决策（用户已确认，不再变更）

| 决策项 | 选择 | 备注 |
|---|---|---|
| 技术地基 | **现有 oiblog**（不推倒重建） | koharu 技术栈已对齐，snow 落后一代 |
| 视觉基调 | **koharu 风格** | 樱花色系、插画头图、波浪分割、大圆角白卡 |
| 字体 | **Maple Mono 等宽** | 保留程序员感，中英文混排优秀 |
| 首页形态 | **引导页 + 博客（snow 式）** | 插画头图 + 中央白卡 |
| 文章列表 | **koharu 式图文交替大卡** | 左图右文 / 右图左文交替 |
| Live2D | **右下角悬浮挂件** | 保留构建期探测降级链 |
| 插画素材 | **用户自放图 + 代码做图库管理** | 扫描 `public/img/gallery/` 自动收集 |
| 评论系统 | **Giscus** | 零服务器成本 |
| Moments | **静态化** | 本地 JSON/YAML → 构建时渲染，**不上 Node adapter** |
| 动效强度 | **三档访客自选** | 灵动 / 克制 / 减弱，localStorage 记忆 |
| 发布形态 | **开源模板 + 高度可配置** | 改 `src/config/` 即换皮 |

### 1.5 明确排除项（不再实现）

| 排除项 | 原因 |
|---|---|
| Node adapter 真动态 | 会破坏纯静态输出，与"零运维"冲突；用静态化替代 |
| i18n 多语言 | 单语站；如需可后续加 |
| 追番 Bangumi | 与博客核心无关 |
| BGM 播放器 | 同上 |
| 圣诞特效 | 季节性功能，收益低 |
| 加密文章 / 答题块 | 已包含在 R4 的 Shoka 全家桶内，作为可选项实现 |
| GSAP / framer-motion | 现有手写 CSS + 原生 JS 足够，减小体积 |

#### 新增 `src/lib/theme-css.ts`（约 90 行）

**核心机制 —— 这是整个模板"可换皮"的关键：**

```
Tailwind v4  @theme inline  →  工具类指向运行时变量
     bg-primary  →  background-color: var(--t-primary)
                    ↑
        theme-css.ts 展开 config/theme.ts 的预设
                    ↑
        BaseLayout 以内联 <style> 注入 <html>
```

```typescript
export function lightVars(): Record<string, string>;   // :root 的 --t-* 变量
export function darkVars(): Record<string, string>;    // html.dark 的 --t-* 变量
export function themeStyleText(): string;              // 完整 <style> 文本
```

生成的 CSS 形如：

```css
:root {
  --t-primary: #e95469;
  --t-primary-light: #ff6b7a;
  /* ... 共 27 个变量 ... */
  --t-radius-sm: 8px;
  --t-shadow-card: 0 16px 32px -20px rgba(40, 12, 32, 0.35), ...;
  --t-reveal-distance: 20px;
  --t-duration: 0.6s;
  --t-ease: cubic-bezier(0.16, 1, 0.3, 1);
  --t-texture: none;
}

```

#### R4.2 插件顺序（**顺序至关重要**）

在 `astro.config.mjs` 中：

```javascript
import { unified } from '@astrojs/markdown-remark';
import remarkDirective from 'remark-directive';
import remarkMath from 'remark-math';
import rehypeKatex from 'rehype-katex';
import { remarkShoka } from './src/lib/markdown/remark-shoka';
// ...

markdown: {
  processor: unified({
    gfm: true,
    remarkPlugins: [
      remarkDirective,          // 1. directive 必须最先（容器语法依赖它）
      remarkMath,               // 2. 数学必须在 ruby/effects 之前
      remarkShoka,              // 3. Shoka 容器/折叠/标签卡
      remarkRuby,               // 4. 注音 {文字^注音}
      remarkSpoiler,            // 5. 剧透 !!隐藏!!
      remarkInlineEffects,      // 6. ++下划线++ ==高亮== ~下标~ ^上标^
    ],
    rehypePlugins: [
      rehypeSlug,
      [rehypeAutolinkHeadings, { behavior: 'append' }],
      rehypeEncrypted,          // 加密块必须最后
      rehypeQuiz,               // 答题块
      rehypeKatex,              // KaTeX
    ],
    syntaxHighlight: { type: 'shiki', excludeLangs: ['mermaid'] },
    shikiConfig: { themes: { light: 'github-light', dark: 'github-dark' } },
  }),
}
```

**顺序约束（踩过坑，必须遵守）：**
1. `remarkDirective` 必须第一 —— Shoka 容器 `:::tip` 依赖 directive 节点
2. `remarkMath` 必须在 `remarkRuby`/`remarkInlineEffects` 之前 —— 否则 `$x^2$` 里的 `^` 会被当成上标标记
3. `rehypeEncrypted` 必须最后 —— 它要加密的是**已渲染完毕**的 children

#### R4.3 Shoka 容器语法

支持 `:::类型 标题` 语法：

| 类型 | 语义 | 渲染 |
|---|---|---|
| `tip` | 提示 | 蓝色左边框 + 💡 |
| `info` | 信息 | 靛蓝 + ℹ |
| `warning` | 警告 | 琥珀 + ⚠ |
| `danger` | 危险 | 红色 + ⛔ |
| `note` / `quote` | 备注 | 灰色 |
| `details` | 折叠 | 可展开块 |
| `tabs` | 标签卡 | 需 React 组件配合 |

数据流：`remark-directive` 产出 `containerDirective` 节点 → 自定义 remark 插件转成 `:::type` 类名 → rehype 阶段包成 `<div class="shoka shoka-tip">`。

#### R6b · AI 摘要

##### 抽取式算法

```typescript
// src/lib/summaries.ts
export function extractSummary(markdown: string, maxChars = 120): string {
  // 1. 剥离 frontmatter、代码块、图片、HTML
  // 2. 分句（中文按 。！？，英文按 .!?）
  // 3. 计算每句权重：
  //    - 词频（分词后 TF）
  //    - 位置权重（首段加权）
  //    - 长度惩罚（太短/太长降权）
  // 4. 取 Top-N 句子，按原文顺序拼接
  // 5. 截断到 maxChars，补省略号
}
```

##### 缓存与产物

```
src/data/cache/summaries.json   # { "<postId>": { "summary": "...", "generatedAt": 1234567890 } }
```

**必须实现增量**：只有内容 hash 变化时才重新生成，否则每次构建都重跑。

```typescript
// 用 md5(post.body) 作为 key，缓存命中则跳过
const key = md5(post.body);
if (cache[key]?.summary) return cache[key].summary;
```

##### UI

文章页顶部的「摘要」折叠面板（koharu 的 `SummaryPanel`），可折叠。

#### R6c · 语义相似推荐

参考 snow 的 `scripts/generateSimilarities.ts`。

##### 依赖

```bash

```

##### 原理

1. 遍历所有文章，取正文（剥离 markdown）
2. 用 transformers.js 的 embedding 模型（如 `Xenova/all-MiniLM-L6-v2`）本地生成 384 维向量
3. 两两计算余弦相似度
4. 每篇文章保留 Top-5 最相似的，存 JSON

##### 缓存

```
src/data/cache/similarities.json
# { "<postId>": [{ "id": "...", "score": 0.87 }, ...] }
```

##### 注意事项

- 模型首次下载约 25MB，需在 `scripts/` 下做缓存目录配置，避免每次 CI 重下
- **这是构建期一次性任务，不进运行时**

##### 主题跟随

```typescript
// 主题切换后同步 Giscus
window.addEventListener('theme-change', () => {
  const frame = document.querySelector('.giscus-frame');
  if (!frame) return;
  frame.contentWindow.postMessage({
    giscus: { setConfig: { theme: document.documentElement.classList.contains('dark') ? 'dark' : 'light' } }
  }, 'https://giscus.app');
});
```

> ⚠️ 注意：`postMessage` 需要 giscus 客户端支持。若不稳定，可改用 `data-theme="preferred_color_scheme"` 一次性交给浏览器判断（更稳，代价是不能手动覆盖）。

### 9.2 推荐的执行顺序与理由

**R4 → R5 → R6 → R7**，理由：

1. **R4 先做**：Markdown 增强影响所有文章的渲染，是内容层地基。且 R4 会改 `content.config.ts`（加 schema 字段），早做早定型，避免 R6/R7 反复改 schema。
2. **R5 次之**：动效系统是横切关注点，R6 的写作室预览也需要遵循 `data-motion`（预览里不应该有滚动浮现动画）。R5 先把 `motion-change` 事件契约定下来。
3. **R6 第三**：最大的一块，且依赖 R4（写作室预览要渲染 Markdown）和 R5（预览遵循动效档位）。
4. **R7 最后**：Comments 和 Moments 是独立模块，不阻塞其它任何一轮。

## 十、给后续执行的关键提醒

1. **每轮只做一块**，做完立刻验证，不要堆积多个未验证的改动。
2. **Node 版本**：所有命令加 `PATH=/usr/local/bin:$PATH`。
3. **构建三步走**：`npm run build`（不是 `astro build`），否则搜索失效。
4. **不要删 `.workbuddy/` 目录**，它是项目数据不是缓存。
5. **配置唯一入口**：组件从 `@/config` 导入，不要直接引 `@/config/site` 或 `@/config/theme`。
6. **新组件的样式**：优先写进 `global.css` 的 `@layer components`，用 `var(--t-*)` 而不是硬编码色值 —— 这是换肤能力的前提。
7. **新增颜色需求**：先加到 `theme.ts` 的 `Palette` 接口和全部预设里，再在组件里用。不要在组件里写死十六进制。
8. **文档同步**：每轮完成后更新本文件的进度表 + `README.md` + `docs/搭建方案.md`。
9. **验收截图**：每轮必须产出 `shots/v2-*.png`，让用户能直接看到进展。
